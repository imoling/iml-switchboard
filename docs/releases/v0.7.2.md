修复版：选了哪个档位、哪个模型就用哪个，Windows 启动时不再闪出命令行窗口。

**修复**

- 手动选了高档、中档或低档，只在这一档的候选里换，不再悄悄升档或降档；这一档都用不了时直接报错。点名了具体模型，就只用这个模型，失败也不换别的型号。自动分档和智能分派照旧可以跨档回退。
- 流式回答中途断开（既没收到结束标记，也没有结束原因）时记为失败，不再当成成功。已经输出了半截内容再出错，就停在这里报错，不会把另一个模型的回答接在后面。
- Codex 的「档位候选」里不再列订阅渠道：Codex 的对话都带工具，订阅接不了，列出来选了也用不上。
- Google AI 订阅暂时从「模型服务」和各处「档位候选」里隐藏：它接不了带工具的请求，选了只会报错。已有的配置原样保留。
- Windows 上启动时不再一闪一闪地弹出命令行窗口。以前后台每检查一次本机的 claude、codex，或者读写一次开机自启，都会闪一下。

**测试**

- 新增测试覆盖：手选档位不跨档、点名模型失败不换模型、同档内仍可换候选、断流记为失败、只发结束原因的服务照常成功、Codex 和全局档位候选不显示 Google 订阅。
- 新增一条源码扫描：后台代码里直接启动子进程会让测试失败，必须走不弹窗口的统一入口。

**说明**

- Windows 的命令行窗口问题是按代码排查修的，没有在 Windows 电脑上实际看过，装好后如果还有闪窗请反馈。

0.7.2 is a fix release. A manually chosen tier now stays within that tier instead of silently moving up or down, and a named model is used as-is with no switch to another model on failure; auto tiering and smart dispatch still fall back across tiers. A stream that ends without an end marker or finish reason is now recorded as a failure, and once partial text has been sent, an error stops there instead of appending another model's answer. Subscription channels no longer appear in Codex's tier candidates, since Codex turns always carry tools. Google AI subscription is hidden from Models and all tier candidates for now; existing settings are kept. On Windows, command windows no longer flash at startup: every subprocess the daemon launches now starts without a console window, and a source scan test keeps it that way.
