修复版：主流模型的上下文窗口按官方值更新，带图消息不再误报超长。

**修复**

- 主流模型的上下文窗口按 2026-11-10 各家官方文档更新：GPT-6.1 Sol/Terra、GPT-6 Sol/Luna/Astra、GPT-5.6 Sol/Terra/Luna 改为 1,050,000；Haiku 5.5 改为 1,000,000；Gemini 3.8 Flash 高/中/低改为 1,048,576；GLM-5.3、GLM-5.3-Flash、Qwen3.8-Max、Qwen3.7-Plus、Qwen3.8-Flash、DeepSeek V4 Pro、DeepSeek Flash、Kimi K3、MiniMax M3 改为 1,000,000。DeepSeek Flash 标为能看图。
- 带图消息不再误报「prompt is too long」：token 估算现在会计入图片（每张按尺寸算，上限 4784 token），count_tokens 接口也算上了图片；超长报错改用官方格式「X tokens > Y maximum」，Y 按窗口的九成算，和 Switchboard 实际判断标准一致，Claude Code 能读出这两个数去压缩。
- 接管 Claude Code 时，/model 菜单里显示「Switchboard 高档/中档/低档」，不再是 router-high/mid/low 的原始名字；关掉接管时这三个显示名会恢复成接管前的值。
- 应用更新后，在后台空闲（busy 为 0）时自动重启一次后台；重启失败会提示「后台重启失败：…」，不会反复重试。
- 「模型」页：Claude Code 被 cc-switch 或接管指到第三方接口时，Claude 订阅卡片不再显示（以前显示「订阅暂停使用」）；停用的账号排到各组最后。

**测试**

- 新增一条测试，把主流型号的官方窗口值固定下来，以后改错了测试会失败。
- 两条旧测试（TestContextWindowFit、TestStickyDropsWhenTooLong）在测试里用 Upsert 把相关型号临时改回小窗口，才能测到「装不下」这种情况。

**说明**

- GLM-5V（128K）、WinWork 网关型号、Fable、Agnes 系列、GPT-5.4 及更早的型号窗口值没核实，保持原样。
- 恢复自动压缩：在 Claude Code 里输入 `/config`，把 Auto-compact 打开，或者在 `~/.claude.json` 里把 `autoCompactEnabled` 改成 `true`。这一项关着时，对话变长就只能报错，没法自动压缩。
