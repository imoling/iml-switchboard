修复版：Codex 接管后不再因为个别工具被 WinWork 网关拒收，检查更新能看到新版本了。

**修复**

- Codex 接管后，有的插件工具把参数定义写成最外层 `anyOf` / `oneOf` / `allOf`，WinWork 网关这类 Anthropic 格式的上游会整轮拒收（400：input_schema does not support oneOf, allOf, or anyOf at the top level）。现在发出去之前先并成普通的对象定义，其余工具原样不动。
- 「给我生成一个漫画的文案」「帮我写一段海报文案」这类要字不要图的说法，不再判成生图；「根据这个文案生成一张漫画图」照旧出图。老配置里没改过的生图规则会自动换成新的。
- 检查更新：以前取 Gitee 发布列表的第一条，列表是旧的在前，拿到的是 0.1.0，一直显示「已是最新」。现在 Gitee 和 GitHub 都查各自的最新正式版，取版本高的；预发布版不再推送。「已是最新」后面带上检查时间。
- 智能分派的理由里写实际在判的判官（本机 Laya、Jev 或那个型号），以前一律写成「Jev 选」。

**安装包**

- Linux 只出 deb 和 rpm，不再出近 100 MB 的 AppImage；Linux 上检查更新改下 deb。

**从 0.6.0 升级**

0.6.0 的检查更新看不到这一版，请手动下载一次：macOS 可以运行 `curl -fsSL https://raw.githubusercontent.com/imoling/iml-switchboard/main/scripts/install-mac.sh | bash`，或者到发布页下载安装包。从 0.6.1 起应用内检查更新恢复正常。

---

0.6.1 is a fix release. Tools whose parameter schema uses a top-level `anyOf` / `oneOf` / `allOf` (some Codex plugin tools) are flattened into a plain object schema before sending, so Anthropic-format upstreams such as the WinWork gateway no longer reject the whole turn with a 400. Requests for text about a picture ("write the script for a comic", "poster copy") are no longer routed to image generation. The update check now asks both Gitee and GitHub for their latest full release and takes the newer one; 0.6.0 always reported itself as up to date, so update from 0.6.0 manually once (the macOS install script or the release page). Smart dispatch reasons now name the judge actually in use. Linux packages are deb and rpm only; the ~100 MB AppImage is gone.
