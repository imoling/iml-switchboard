# Switchboard · 使用指南

## 安装后第一次打开

1. 打开应用，菜单栏出现分流图标。首次引导分四步：检测本机 CLI → 添加一个按量付费账号 → 接入 Claude Code → 试一句。
2. 本机已登录的 `claude`、`codex` 命令会自动出现在「模型」里，应用不碰任何登录信息。只装了 ChatGPT 桌面版也行：它自带一份 `codex` 命令，Switchboard 会在应用包里找到它。
3. 添加按量付费账号时粘贴密钥即可，密钥只存在这台电脑的钥匙串里。支持智谱、阿里云百炼、DeepSeek、Moonshot、MiniMax、Agnes AI、OpenRouter、Anthropic、302.ai。
   其中 Agnes AI 一把密钥同时覆盖文本、生图和生视频，添加后会自动成为图片和视频的兜底渠道。

## Windows 上有什么不同

- 菜单栏换成右下角托盘，左键点开弹窗，右键是菜单。
- 快速面板的快捷键默认是 Ctrl + Alt + Space（Alt + Space 在 Windows 上是窗口菜单）。
- 数据在 `%AppData%\Switchboard`；按量付费密钥存在「凭据管理器 → Windows 凭据」里，名为 iML Switchboard 的条目。
- 开机自启写在当前用户的「登录时启动」项里，后台不弹命令行窗口，日志在数据目录的 `logs\serve.log`。
- 用 npm 装的 `claude` 是 `.cmd` 包装，宿主传来的系统提示会改从标准输入交给它，不放在命令行参数里。

## 在 VS Code 里怎么用

接入 Claude Code 后，VS Code 里的 Claude Code 面板多了五个工具：生图、生视频、做动画、问别的模型、查任务进度。
VS Code 扩展和命令行共用配置，不用再单独设置；重新加载窗口或新开对话即可生效。首次调用时点「始终允许」。

直接用自然语言说要做什么，例如：

```
给 README 配一张封面图，再把 logs/ 里的报错归类
```

Claude 自己规划（消耗订阅额度），把封面交给生图工具（调度台选模型），把归类交给便宜模型（几分钱）。

想指定方式就直接说：「这个让便宜模型做」「用最好的模型画」「做成 5 秒视频」「问问 GPT 的意见」。

装了自定义命令后也可以打：`/iml-img 一张科技感封面`、`/iml-video …`、`/iml-anim …`、`/iml-cheap …`、`/iml-second …`。

主对话始终是你订阅的 Claude，调度台只接手 Claude 派出来的活。

## 显式指令（在调度台直接处理的请求里有效）

| 写法 | 效果 |
|---|---|
| `/fable`、「仔细想」、「想清楚再答」 | 顶配 Fable |
| `/opus`、`/hard` | 高档 |
| `/quick`、`/cheap` | 低档 |
| `/sub` | 只用订阅 |
| `/img-best` | 媒体用最好档 |

这些指令在快速面板、WorkBuddy、Hermes 的请求里有效。在 Claude Code 里请用自然语言，Claude Code 自己有一套斜杠命令。

## 档位候选：每档先试谁

低、中、高三档各有一张候选表：哪些渠道的型号进这一档、谁先试。表有两层：

- 全局的在「分派」的「档位候选」里排，所有宿主默认照它。
- 每个宿主可以在「宿主」页自己那张卡片的「档位候选」里另排，只对这个宿主生效；没自己排的档跟全局。比如 WorkBuddy 的高档先试 WinWork OS，Codex 的高档先试 Claude 订阅。

勾选、排序后保存，立刻生效；宿主菜单里选「低档」「中档」「高档」或「自动分档」落到这一档时都照它来。

- 表只管先后和取舍，型号本身在「模型」里定：订阅渠道出它这一档选的那个型号，按量付费账号出它这一档的型号列表；那边改了，这边跟着变。
- 没排过的档按内置规则走：低档先按量付费（免费型号排前面），中高档先 Claude 订阅。
- 带工具的请求跳过订阅条目，所以排第一的是订阅时，智能体回合会落到后面的按量付费。
- 表里的条目全失效了（账号删了、渠道关了）就往下一层找：宿主的表失效用全局的，全局的也失效用内置规则，不会整档没人用。「回到默认」「改回跟全局」撤掉手排。

## 订阅在哪些地方用得上

订阅额度只由未修改的官方命令行子进程消耗，这个子进程跑不了宿主自己定义的工具，所以只有不带工具的请求能走到订阅：

- 各宿主的派活工具（问模型、第二意见）：中档、高档先到 Claude 订阅。
- 宿主菜单里的「订阅优先」：只接不带工具的纯对话，带工具会直接报错让宿主改用「自动分档」。
- 接管（Claude Code、Claude Desktop、Codex）和带工具的智能体回合（WorkBuddy 任务、Codex 主对话）一律走按量付费或 WinWork。

## 用 WinWork 的模型

WinWork 只有开着时才把网关令牌放在配置里，退出或登出就删掉，这是它自己的设计，Switchboard 也不保存令牌。所以请求要走 WinWork 而它没开时，Switchboard 会在后台隐藏启动它，等令牌写好再发，第一条请求会慢几秒。查看状态、打开模型页都不会启动它。

启动不成功（比如登录过期）时，这个账号歇 30 秒，请求换下一个账号；2 分钟内不再重复启动，这期间你手动打开 WinWork 也能立刻恢复。

## 概览

总览页的「接入 N 个 · 渠道 M 个」那一行默认收起，点开是全貌（开合记住）：左边是已接入的智能体，中间是调度，右边是渠道。连线越粗派活越多，虚线表示近 7 天没用过。每完成一次请求，就有一个光点从发起方经中间走到干活的渠道，陶土色是订阅，蓝色是按量付费，绿色是媒体，红色是失败。打开页面时会把最近 6 次走一遍，之后只跟着真实请求动。点节点跳到宿主页或模型页。系统开了「减弱动态效果」时不放光点。

## 彩蛋

侧栏「设置」下面的「彩蛋」是一张会动的像素画，演的是每一次请求里应用和模型怎么来回：应用在左边，判档的在中间，模型按档位住在右边的楼里，出图出视频的在底下。来一单，信使把信送到中间；判档的把活交给某一层的模型；模型干完再回给应用。换人、改判、请应用跑工具、异步出视频、退回太长的请求，都有各自的演法，画面下方的旁白一行一件事。画面跟着风格主题换：标准是写字楼，点将台是河边大营，魔法学院是湖边的塔楼，后宫是宫城，海王是码头和海底；投屏模式下是写字楼。

没活的时候模型会互相搭话。每个型号有固定的性格（由名字算出来）：亲碳派喜欢人类，嘲碳派吐槽人类，再配一种脾气，嫌活杂、嘲牛马、佛系或者卷王。接到活、交差、失手、半夜还在派活、额度快见底，都会嘀咕两句。点一下某个模型，它挥手说一句，卡片里能看到它住哪层、什么性格；点判档的那位也会回话。

右上角「名牌」开关控制要不要一直显示名字（默认只在干活和鼠标悬停时显示）；「演示」是一段 70 秒的固定剧本，七种来回和额度用完、评估都在里面，没接应用时也能看。把一个模型拖到更高的一层，就是把它最近那单记成判低了、请高一档重做（会确认，可能另外花钱）。天气跟着状态变：刚有报错下雨，订阅额度紧张下雪（海王是起雾），晚上有月亮。窗口藏起来时不画，帧率封顶 30。

## 实验功能

设置最下面的「实验功能」可能改动或去掉；刘海动画只在 macOS 上显示。

刘海动画：打开后，请求经过时黑色从刘海两侧和下方长出来，左边是智能体，右边是干活的模型。一次请求是一来一回：光从左边飞到右边，模型干活时右边转一圈光，做完光飞回左边炸开，失败时是红光，整条带子抖一下。颜色和总览页同色系。连发时两耳保持展开，约 1.5 秒没有新请求就收回；跑了 6 秒还没完的长任务会收窄、放慢。鼠标穿透，下面的菜单照常能点。外接显示器和合盖时不显示；合盖启动的话，打开盖子后要重开一次开关。

状态栏图标：菜单栏里用哪种样子，八种可选（底板、线框、无框、插线板、拨杆开关、破框、像素主帅、三档阶梯），点了立刻换。正常态是单色模板图，跟着菜单栏深浅反白；额度告警、出错两张带色点，不做模板，深色菜单栏下底板会和菜单栏融在一起，只剩色点。

## 菜单栏

- 今天的次数、按量花费、比全用 Opus 省了多少。
- 各订阅的额度条是本应用按用量估算的，以官方显示为准。额度过了让出线，低档和中档任务自动改走按量付费。
- 调度模式：省钱（高档降中档）、均衡、质量（困难任务用 Fable）。
- 投屏模式：一键切回标准主题，投屏、讲课前点一下。

## 接管 Claude Code / Claude Desktop / Codex

宿主页里这三个宿主各有一个「接管模型」开关，互不影响。打开后：

- Claude Code：`~/.claude/settings.json` 的 env 指向本机的 Switchboard，opus / sonnet / haiku 分别映射成高档 / 中档 / 低档，默认模型是「自动分档」。不用重启，`/model` 里输 `router-auto`、`router-high`、`router-mid`、`router-low` 或任何按量付费型号（比如 `winwork-snt-5.5`）。接管期间 Claude 订阅渠道暂停，关掉开关即恢复。
- Claude Desktop：它和 Claude Code 是两个入口，不看 `settings.json`。接管会在 `Claude-3p/configLibrary` 加一份指向本机 Switchboard 的配置并选中，再切到第三方模式；要完全退出（macOS 上按 ⌘Q）再打开才生效。模型菜单里是「自动分档」「高档」「中档」「低档」四项：Desktop 只收 Claude 家的型号名，这四项实际借用 `claude-sonnet-5`、`claude-opus-5`、`claude-sonnet-4-6`、`claude-haiku-5-5` 的名字，请求还是按档位走。第三方模式有单独的数据目录，官方模式下的对话看不到；关掉开关、重开 Desktop 就回到官方登录。
- Codex：`~/.codex/config.toml` 多一个 `switchboard` 供应商（Responses 协议，密钥在请求头里，登录文件不动）并切过去，同时生成模型目录（数据目录的 `codex-model-catalog.json`），`/model` 里能选四个档位和按量付费型号。Codex 只在启动时读目录，打开接管、增减账号后都要彻底重启它。目录由本机 Codex 试读通过才启用；没通过时接管照常，只是 `/model` 里看不到档位。
- 终端里设了全局代理的话，Codex 要在 shell 里加 `NO_PROXY=127.0.0.1,localhost`；Claude Code 的这一项接管时已经替你写进 settings 的 env。
- 原来的值都存在数据目录的 `takeover-*.json` 里，关掉开关逐个放回。
- CC Switch 这类工具改的是同一批配置文件，谁后写谁生效。由 Switchboard 接管的宿主，别再用它们切换。

## 纠偏

结果不满意，在总览的记录表里点一条，再点「这次判低了」。同一类任务 7 天内被标记 5 次，分派页会给出调高一档的建议，并写明每周多花多少。

## 接入其他智能体

- Codex：宿主页点「接入」，会用 `codex mcp add` 注册 Switchboard，并在 `~/.codex/AGENTS.md` 末尾加一段调用约定；下次启动 Codex 生效。
- Gemini CLI：宿主页点「接入」，会用 `gemini mcp add -s user` 注册，并在 `~/.gemini/GEMINI.md` 末尾加一段调用约定；下次启动生效。
- 豆包工作：宿主页「复制配置」，到豆包工作左侧「技能 · 连接器 · 伙伴」→「新建」→「新建自定义连接器」里填。桌面版支持本地命令（推荐，命令 `imls`、参数 `mcp`）和 HTTP 两种；HTTP 地址是 `http://127.0.0.1:18081/mcp`，请求头带门面密钥。连接器存在豆包工作自己的账号里，本机没有可改的文件，所以只能这样填；填好并派过一次活之后，宿主页会显示「已接入」。
- pi：宿主页点「接入」，会往 `~/.pi/agent/models.json` 合并一个 `switchboard` 提供方；之后 `pi --provider switchboard --model router-auto`。
- DeepSeek Harness：宿主页点「接入」，会往 `~/.dsh/cordis.patch.yml` 加一个 Switchboard 提供方，密钥引用写在 `~/.dsh/.env`；之后在 `dsh web` 的模型列表里选 Switchboard。只装了桌面版、`dsh` 还没进 PATH 也认：数据目录里有它自己建的 profiles、sessions 就算装了。
- OpenClaw：宿主页点「接入」，会往 `~/.openclaw/openclaw.json` 的 `models.providers` 合并一个 `switchboard` 提供方；之后 `openclaw agent --model switchboard/router-auto`，或在会话里用 /model 选。文件带注释时改不了，复制片段手动合并。
- Hermes：宿主页点「接入」，会在 `~/.hermes/config.yaml` 里加 MCP 和生图配置，原文件先备份为 `.bak-imls-时间`。接入后卡片里多一个「接管模型」开关：打开把它的 `model` 段改成 Switchboard 的兼容接口（型号 `router-auto`，走按量付费），原来的 `model` 段存在数据目录的 `takeover-hermes.yaml`，关掉原样放回；重启 Hermes 生效。
- WinWork 的模型给别的宿主用：装了 WinWork 并登录过，「模型」的订阅那组会自动多一行 WinWork，标「不计费」，只有停用和启用；它网关里的型号（Sonnet 5.5、DeepSeek、Qwen、Kimi 等）按档位参与调度，不计费；WorkBuddy 接入时这些型号也会单独出现在它的模型列表里，可以直接选。
- WinWork：宿主页点「接入」。WinWork 内嵌了一份 Claude Code，配置在 `~/.kooky-data/claude-config`；接入会往它的 `.claude.json` 登记工具、写调用约定、装斜杠命令，动之前会留一份 `.claude.json.bak-switchboard`。下次新建会话生效。
- WorkBuddy：宿主页点「接入」，会往 `~/.workbuddy/models.json` 加 Switchboard 的型号：「Switchboard 自动分档」、三个档位、「Switchboard 订阅优先」（无工具单轮），以及各账号分进档位的型号（名字前带「Switchboard ·」）。也可以复制片段手动填。

Codex（接管时）、WorkBuddy、pi、DeepSeek Harness、OpenClaw 的菜单里列哪些型号，在宿主页该宿主的「模型列表」里定。默认是自动分档、三个档位、订阅优先（Codex 没有）加每个按量付费账号分进档位的型号，新加账号自动进表；服务自己报出来但没分档位的型号也能勾上。自己勾选、排序后第一个就是宿主的默认型号，保存后立刻写进宿主的配置，重启宿主生效；「回到默认」撤掉自己的排法。

改动过的文件都会先备份为 `.bak-imls-时间`；点「断开」只删 Switchboard 自己加的那部分。

宿主页左边是宿主列表（已接入、可接入、未安装），右边是选中宿主的开关和写进去的内容；标题下显示近 7 天派过几次活。pi、OpenClaw、DeepSeek Harness 是在这个版本之前接入的话，断开再接入一次才能计上。

终端里全局设了代理（`HTTP_PROXY`、`HTTPS_PROXY`）时，pi、OpenClaw、DeepSeek Harness 会把发往本机的请求也交给代理，报「Connection error」。在同一处加上 `NO_PROXY=127.0.0.1,localhost` 即可；`imls doctor` 会检查这一项。

## 和 cc-switch、magpie 一起用

它们管的是「Claude Code、Codex 背后用哪家的模型」，Switchboard 管的是「宿主把哪些活派给别的模型」，可以同时开。

- 用 cc-switch 把 Claude Code 切到第三方接口时，Claude 订阅渠道会自动暂停，同档任务改走其他渠道；切回官方登录后自动恢复。模型页会显示原因。
- 用 magpie 时，Claude Code 照常接入 Switchboard 即可；如果想让 magpie 管理的智能体也能派活，把 `http://127.0.0.1:18081/v1` 和门面密钥填成它的一个自定义提供方，模型选 `router-auto`。

## 命令行

```
imls serve          # 常驻后台
imls route "任务"    # 只看决策
imls route --run "任务"
imls stats          # 本周摘要
imls doctor         # 检查 CLI、Node、账号，以及官方 CLI 的参数有没有变
imls golden         # 把「判低了」的请求导出成路由金标候选
imls install        # 注册开机自启
```
